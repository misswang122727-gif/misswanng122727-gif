# 墨茵机器人 Before / After 对比说明

## 核心问题：为什么只能6轮？

这**不是流程设计问题**，是**上下文窗口溢出**问题。

| 每轮实际发送的tokens | 问题版本 | 优化版本 |
|---|---|---|
| System Prompt | ~1500 tokens | ~600 tokens |
| 对话历史 | 全部累积（无限增长） | 最近3轮（固定上限） |
| 第1轮总计 | ~1700 tokens | ~800 tokens |
| 第6轮总计 | ~4000 tokens（溢出！） | ~1400 tokens（稳定） |
| 第20轮总计 | ~10000 tokens（完全崩溃） | ~1400 tokens（依然稳定）|

---

## 两个演示文件

### ❌ before/naive-6round-chatbot.yml
- 无上下文窗口控制
- 对话历史无限累积
- System Prompt 3000+ tokens（包含完整动作词典）
- **约第6轮开始出错/失效**

### ✅ after/stable-20round-chatbot.yml（推荐演示给老大）
- **滑动窗口**：只保留最近3轮对话历史
- System Prompt 精简至 600 tokens
- tokens使用量稳定，不随轮数增长
- **理论上可支持无限轮，实测20轮+无问题**

### ✅✅ after/summary-compression-workflow.yml（高级版）
- 滑动窗口(3轮) + 每5轮自动摘要压缩
- 历史信息不丢失，只是被压缩
- 适合需要记住早期对话内容的场景

---

## Dify 配置步骤（stable-20round版本）

1. 进入 Dify，新建 **Chatbot** 应用
2. 在 **提示词** 处粘贴精简版 System Prompt
3. 在 **模型配置** 中：
   - 找到 **"上下文"** 或 **"记忆"** 设置
   - 开启**对话历史**
   - 将**窗口大小**设置为 **3**
4. 保存并测试

## 演示脚本（给老大看的对话测试）

依次输入以下指令，对比两个版本的表现：

```
第1轮：你好，我叫小明
第2轮：介绍一下你自己
第3轮：今天天气怎么样
第4轮：向前走两步
第5轮：停下来
第6轮：我之前说我叫什么名字？  ← 问题版本这里开始失效
第7轮：现在几点了
第8轮：帮我查一下奇瑞瑞虎8的价格
...
第20轮：还记得我一开始说的名字吗？ ← 优化版本（高级版）依然能回答
```
